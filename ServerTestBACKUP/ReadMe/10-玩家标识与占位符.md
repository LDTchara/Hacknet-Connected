# 玩家标识与寻址

## 需求

多人下需要精确指定某个特定玩家，不只是"所有玩家"或"触发者"。

## ID 分配方案

### 原则
- 第一次连接时分配 ID，按顺序递增（1, 2, 3...）
- 掉线重连时按名字找回旧 ID，继续使用
- 玩家彻底离开（超时）后，ID 释放给后来的人
- **ID 与对应玩家身份一起持久化。** 存档时存 playerId→playerName 映射表，
  读档时按名字找回旧 ID。详见三层架构中的 Player Layer。

### 分配流程

```
A 连上来 → 没有旧 ID → 分配 ID=1
B 连上来 → 没有旧 ID → 分配 ID=2
A 掉线 → ID=1 保留（等待重连）
A 超时（5分钟） → ID=1 释放
C 连上来 → 分配 ID=1（或 3，视实现而定）
```

### 持久化
- ID 不存进存档，存档只存账户名
- 重连时查 `playerName → playerId` 映射表
- 同一局内 ID 不变

## Player 占位符体系

### 现有占位符（原版 ComputerLoader.filter()）

```
#PLAYERNAME#          → ComputerLoader.os.defaultUser.name
#PLAYER_IP#           → ComputerLoader.os.thisComputer.ip
#PLAYER_ACCOUNT_PASSWORD# → SaveFileManager.LastLoggedInUser.Password
#RANDOM_IP#           → NetworkMap.generateRandomIP()
```

多人下语义：
- `isPublic=false`（私人）：每人自己的名字 ✅
- `isPublic=true`（全局）：触发者的名字 ✅
- 不需要改成逗号分隔所有玩家

### 新增索引化占位符

```
#PLAYER_0#            → 玩家 ID=0 的名字
#PLAYER_1#            → 玩家 ID=1 的名字
#PLAYER_IP_0#         → 玩家 ID=0 的节点 IP
#PLAYER_IP_1#         → 玩家 ID=1 的节点 IP
```

用途：全局 Action 中指定某个特定玩家，不管谁触发的。

### 预处理层

索引化占位符需要一层预处理，放在 `ComputerLoader.filter()` 之前：

1. 联机模组拦截文本 → 替换 `#PLAYER_XXX#`
2. 查玩家列表拿名字/IP → 替换
3. 剩下的非索引占位符交给 `ComputerLoader.filter()` 处理

不需要改原版代码，加一个静态方法在联机模组里。

## 文件内容烘焙问题

### 问题

`ComputerLoader.filter()` 在 Action 写入文件时就被调用了，替换后的内容直接落盘。共享节点上的文件内容是烘焙死的，不同玩家读到同一份内容。

```
CopyAsset destComp="sharedNode" file="#PLAYERNAME#.txt"
  → 写入时 filter → "Alice.txt" 落盘
  → Bob 读 → 显示 "Alice.txt"（但 Bob 叫 Bob）
```

### 解法

写入共享文件前**跳过替换**，保留占位符原样。靠读取时的 `ComputerLoader.filter()` 做本地替换。文件内容不烘焙：

```
文件存 "#PLAYERNAME#"
Alice 读 → filter → "Alice"
Bob   读 → filter → "Bob"
```

文件名不经过 `ComputerLoader.filter()`，需要单独处理。但文件名含占位符的情况极少，属于边界问题。

### 影响范围

| 场景 | 写入替换（原版） | 读取替换（联机） |
|------|----------------|----------------|
| IRC 消息 | 不落文件，不影响 | 不变 |
| 邮件 body | 落文件但显示时再过 filter → 实际也正确 | 不变 |
| 共享节点文件内容 | ❌ 烘焙，所有人看到一样的 | ✅ 每人自己替换 |
| `playerComp` 文件 | ✅ 自己电脑，名字对 | ✅ 不变 |
| 文件名 | ❌ 烘焙，不经过 filter | ⚠️ 边界情况 |
