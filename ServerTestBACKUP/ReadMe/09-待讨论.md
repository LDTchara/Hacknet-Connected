# 待讨论 / 待定

## 已解决

| 项目 | 结论 |
|------|------|
| isPublic 放哪一层 | Condition 层 + Action 层都支持，继承 + 覆盖（同 Delay） |
| Faction isPublic 默认值 | false（与其他类型区别对待） |
| 共享 vs 独立 Rank | LDT 推荐共享，AC 倾向共享，未拍板 |
| 掉线处理 | 客户端本地临时存档 + 拉世界进度同步 |
| 联机模组形态 | 扩展模组，不是全局模组 |
| 玩家 ID 持久化 | 存档时存 playerId->playerName 映射表 |
| 占位符写入烘焙 | 共享节点写入前跳过替换，读取时本地 filter |
| 无头服务器 | 当前不考虑，默认必须 Windows + 屏幕 + 音频 |
| VERT | 暂时无活动，不追 |

## 待讨论

### Rank 模式（未拍板）
- LDT 推荐共享，AC 倾向共享但不太放心
- 共享下的分支任务怎么做（Flag 分支 + 房主选/投票）
- 自由度 vs 兼容性的取舍

### 大厅（Lobby）
- 是否需要？选号/选角色/分配玩家 ID
- 与 ExtensionsMenuScreen 的整合
- 玩家选 ID 的场景（某人想当 2 号因为有特殊剧情）

### 服务器列表 / 扩展分发
- 服务器名字、运行中的扩展、人数、版本
- 自动同步扩展文件

### 完整连接生命周期
- 大厅 -> 入网同步 -> 游玩 -> 掉线/重连 -> 增量同步
- 断线后其他玩家怎么办（暂停 / 继续 / 强制下线所有人）
- 超时释放时间阈值

### 服务端架构
- 主机模式足够还是需要纯 C/S
- 迁移路径：主机模式 -> 抽 GameState -> 替换为无头服务器
- 目前无 Linux 测试环境，坚持有头模式是否最优解

### 客户端可信度
- 预期完全不可信 -> 验证写进 ServerPlugin
- 每次连接都要全量同步吗？不，增量同步（操作日志方案 B）

### KE 扩展与联机
- KE 自定义 Action 是 DelayablePathfinderAction -> 加 isPublic 属性字段即可
- CustomTrial/PhaseSwift 等场景级扩展是否要特殊处理

### 存储与同步
- 世界层和玩家层各用一条独立的变更日志
- 层间操作同步顺序：按 Delay 顺序发
- 全量同步范围：世界层全发，玩家层只发目标玩家的
- 修改权限：全服务端权威，客户端不可信
