## 背景：两类占位符

| 类型 | 示例 | 两端值 | 替换方式 |
|------|------|--------|---------|
| 内置通用 | `#PLAYERNAME#` `#PLAYER_IP#` | **不同**（Alice / Bob） | 各自本地 `ComputerLoader.filter()` 替换，不跨端同步 |
| 全局身份索引 | `#P1NAME#` `#P2IP#` | **相同**（两端都=Alice） | 开局大厅选择身份后映射表统一替换 |
| 局内任务身份 | `#P1_M1_BRANCH#` | **相同** | 局内支线触发时绑定参与玩家，任务内使用 |

`#PLAYERNAME#` 在主机模式下不需要额外处理——Action 只在服务端执行，客户端看到服务端名是合理的，不需要反替换机制。

全局身份索引满足"知道 P1 是 Alice，P2 是 Bob"。但拓展作者写一个 2 人合作支线时，他需要在任务中间引用"P1 在这个任务里选的分支"，而游戏开始前他不知道哪个玩家会在哪个分支里。所以需要局内任务级别的身份绑定：

```
大厅定义全局身份: P1 = Alice, P2 = Bob
         ↓
触发支线 "双人入侵":
  该任务可能 3 选 2 参与
  任务内部用 #P1_M1_BRANCH# 表示"参与此任务的 P1 所选分支"
  → 替换为 "alice_branch_2"（Alice 在这任务里选的分支）
```

## P1 — 身份系统（#6 ~ #12）

### 整体流程

#### 第一阶段：开局大厅（全局身份绑定）

```
服务端启动 → 选扩展 → 解析 Multiplayer/PlayerSlots
              ↓
         开准备大厅，等待 requiredPlayers 人连入
              ↓ 客户端连入 → 选空闲 slot
         slot 锁定，记录 playerId → slotId 映射
              ↓ 满员 → 下发全局身份映射表
         各客户端保存全局映射
              ↓
         每个实例找到自己的 type="player" 节点设为 os.thisComputer
         其他 player 节点保留为普通网络节点
              ↓
         游戏开始
```

#### 第二阶段：局内支线（任务身份绑定）

```
游戏进行中，触发一个需要 N 人参与的支线任务
              ↓
     任务声明需要的身份槽位数（如 2 人）
          ↓
     游戏中弹窗/通知，让合适的玩家接取
     或系统自动分配给在线玩家
          ↓
     该次任务的参与者确定后，
     #P1_M1_BRANCH# → 任务内 P1 在该分支的选择
     #P2_M1_FLAG#   → 任务内 P2 的某个状态
     由任务 Action 在运行时通过 IdentityMissionScope 管理
```

### 拓展声明格式

拓展的 `extension.xml` 或入口文件中声明：

```xml
<Multiplayer requiredPlayers="3">
  <PlayerSlot id="1" name="黑客"   computer="playerComp_alice"/>
  <PlayerSlot id="2" name="内鬼"   computer="playerComp_bob"/>
  <PlayerSlot id="3" name="指挥"   computer="playerComp_charlie"/>
</Multiplayer>
```

- `requiredPlayers`：**定值**，缺一人不能开局，多一人不能连入
- 每个 slot 绑定一个 `type="player"` 的计算机 idname

### #6 拓展声明 PlayerSlots

服务端加载扩展时解析 `<Multiplayer requiredPlayers="N">`，按 `requiredPlayers` 决定准备大厅需要等待的人数。每个 slot 的 `computer` 属性指向 `type="player"` 节点。

### #7 准备大厅 UI

```
┌─────────────────────────────┐
│  MyMission - 准备大厅        │
│                             │
│  P1 黑客    ■ Alice     [就绪] │
│  P2 内鬼    ■ Bob       [就绪] │
│  P3 指挥    □ 等待...         │
│                             │
│            [ 2/3 人 - 等待 ]   │
└─────────────────────────────┘
```

流程：
1. 服务端建厅 → 广播可用扩展列表
2. 客户端连入 → 看到可用扩展 → 选一个 → 进 Lobby
3. 客户端看到空闲 slot → 选一个 → 锁定
4. 服务端确认满员 → 分发映射表 → 所有人开始游戏

**实现**：新 UI Screen 或在 ExtensionsMenuScreen 上叠加。

### #8 连接时协商 slot 分配

**协议**（Terminal ↔ Client，LiteNetLib）：

```
服务端 → 客户端: LOBBY_INFO:extensionName:slotCount
客户端 → 服务端: LOBBY_JOIN:slotId
服务端 → 客户端: LOBBY_CONFIRM:slotId:playerId
...
满员后:
服务端 → 全体: GAME_START:slotMappingJson
```

`slotMappingJson` 包含每个 slot 绑定到哪个玩家，两端据此构建身份映射。

### #9 玩家计算机分配

**时机**：大厅关闭、游戏开始前。

每个实例根据映射表找到自己的计算机节点：

```csharp
var mySlotId = GetMySlotId(); // 当前实例分配到的 slot id
var myComputerId = slotDefs[mySlotId].computer; // 如 "playerComp_alice"

foreach (var node in os.netMap.nodes)
{
    if (node.idName == myComputerId)
        os.thisComputer = node;
}
// 其他 type="player" 节点保留为普通可访问节点
```

### #10 身份映射替换层

在 `ComputerLoader.filter()` 完成后额外调用，把 `#P1NAME#` 等换成实际值：

```csharp
internal static class IdentityPlaceholderResolver
{
    public static Dictionary<int, PlayerIdentity>? Identities;

    // 在 filter() 替换链末尾调用
    public static string Resolve(string content)
    {
        if (Identities == null) return content;
        for (int i = 1; i <= Identities.Count; i++)
        {
            if (Identities.TryGetValue(i, out var id))
            {
                content = content
                    .Replace($"#P{i}NAME#", id.Name)
                    .Replace($"#P{i}IP#",   id.IP);
            }
        }
        return content;
    }
}
```

替换链：
```
ComputerLoader.filter(content)     → #PLAYERNAME# 等已替换
  → IdentityPlaceholderResolver.Resolve(content)  → #P1NAME# 等已替换
  → 写入文件
```

`IdentityPlaceholderResolver.Resolve` 在每一端都调用，但使用同一份映射表（服务端分发），所以 `#P1NAME#` 在两端的替换结果一致。

### #11 索引占位符支持列表

#### 全局身份占位符（大厅决定）

| 占位符 | 来源 |
|--------|------|
| `#P1NAME#` ~ `#P4NAME#` | `Identities[i].Name` |
| `#P1IP#` ~ `#P4IP#` | `Identities[i].IP` |
| `#P1COMP#` ~ `#P4COMP#` | `Identities[i].ComputerId` |

至少支持 4 个 slot。

#### 局内任务身份占位符（支线触发时决定）

格式：`#P{slotId}_{missionId}_{key}#`

```
#P1_M1_BRANCH#      → 任务 M1 中 P1 所走的分支名
#P2_FINAL_CHOICE#   → 某任务中 P2 的最终选择
```

这些占位符不由 `IdentityPlaceholderResolver` 静态替换，而是由触发该支线时创建的 `IdentityMissionScope` 对象管理：

```csharp
public class IdentityMissionScope
{
    public string MissionId { get; }
    public Dictionary<string, string> Variables { get; } = new();

    public string Resolve(string content)
    {
        foreach (var kv in Variables)
            content = content.Replace($"#P1_{MissionId}_{kv.Key}#", kv.Value);
        return content;
    }
}
```

作用范围限单次任务，任务结束后释放。占位符键名由拓展作者自行定义。

### #12 身份数据模型

```csharp
public class PlayerIdentity
{
    public int SlotId { get; set; }       // 对应 <PlayerSlot id="1">
    public string Name { get; set; }      // 该 slot 绑定的玩家名
    public string IP { get; set; }        // 该 slot 绑定的玩家 IP
    public string ComputerId { get; set; } // 该 slot 绑定的计算机 idname
}
```

映射表由服务端构建，客户端在 `GAME_START` 时收到并存入 `IdentityPlaceholderResolver.Identities`。

## P2 — 拓展规范（#15 ~ #16）

### #15 检测硬编码玩家节点引用

在 Action 执行层（`HackerScriptExecuter`、`SAAddAsset` 等）拦截对 `type="player"` 节点的直接引用：

```csharp
foreach (var node in os.netMap.nodes.Where(n => n.idName.StartsWith("playerComp")))
{
    if (actionContent.Contains(node.ip))
        Log.Warn($"硬编码玩家节点IP: {node.ip}，请改用 #P1IP#");
}
```

### #16 拓展编写文档

说明以下规范：

- 如何定义 `<Multiplayer requiredPlayers>` 和 `<PlayerSlot>`
- `requiredPlayers` 是定值，不支持范围或可选
- `type="player"` 节点的 idname 命名建议（如 `playerComp_alice`）
- 可用占位符列表

#### 通用占位符（内置，各自本地替换）

| 占位符 | 替换为（本地 OS） | 说明 |
|--------|-----------------|------|
| `#PLAYERNAME#` | `os.defaultUser.name` | 当前玩家名字 |
| `#PLAYER_IP#` | `os.thisComputer.ip` | 当前玩家电脑 IP |
| `#PLAYER_ACCOUNT_PASSWORD#` | 当前登录用户密码 | 当前玩家账户密码 |

#### 全局身份索引占位符（大厅决定，两端一致）

| 占位符 | 替换为 |
|--------|-------|
| `#P1NAME#` `#P2NAME#` `#P3NAME#` `#P4NAME#` | 各 slot 玩家名字 |
| `#P1IP#` `#P2IP#` `#P3IP#` `#P4IP#` | 各 slot 玩家电脑 IP |
| `#P1COMP#` `#P2COMP#` `#P3COMP#` `#P4COMP#` | 各 slot 玩家计算机 idname |

#### 局内任务身份占位符（支线触发时决定，任务内有效）

格式：`#P{slotId}_{任意自定义键}#`

| 示例 | 说明 |
|------|------|
| `#P1_M1_BRANCH#` | 任务 M1 中 P1 所选分支 |
| `#P2_LOOT#` | P2 在该任务中获取的物品 |

- **禁止硬编码** `type="player"` 节点的 IP 地址，必须使用占位符
- 引用其他玩家时用 `#P1NAME#`（P1 不一定是自己），引用自己时仍用 `#PLAYERNAME#`
- 局内任务占位符的键名由拓展作者自定义，通过 `IdentityMissionScope` 注入
