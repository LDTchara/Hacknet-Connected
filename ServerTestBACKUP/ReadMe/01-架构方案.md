# 联机模组架构方案（当前实际走向）

> 参与: LDT, AC
> VERT 自 2026-06-19 起无活动（一个月的验证层工作量被否定后情绪低落）

## 当前架构：主机模式

AC 选定主机模式作为务实起点。服务端跑一份完整的 Hacknet + PF + 所有模组实例。
不要求无头服务器。

```
                       NamedPipe                      LiteNetLib UDP
Hacknet 游戏进程 ───────── HacknetServerTerminal ────────── 远程客户端
├─ ServerClientEventsMod       ├─ Pipe 事件转发            │
│  (事件检测层)                ├─ CommandHandler          TestClient
├─ ServerPlugin                ├─ NetworkManager          (多个)
│  ├─ EventForwarder           └─ ServerStorage (INI)
│  ├─ ServerManager
│  └─ Harmony Patches
```

## 各组件职责

| 组件 | 说明 |
|------|------|
| ServerClientEventsMod | AC 独立项目。Harmony Prefix/Postfix 捕获 15+ 类型游戏操作，统一事件总线 |
| ServerPlugin | BepInEx 模组，跑在游戏进程内。订阅事件 → 格式化 EVENT:TYPE:data → Pipe 发送 |
| HacknetServerTerminal | 纯 .NET 控制台。NamedPipe 服务端 + LiteNetLib UDP 9050 转发给远程客户端 |
| TestClient | 远程客户端示例，通过 LiteNetLib 连接 |

## NamedPipe 的作用

游戏进程（ServerPlugin）与控制台进程（HacknetServerTerminal）之间需要进程间通信。
NamedPipe 比 TCP loopback 快、无端口冲突、只允许本机。控制台是 Pipe 服务端（先启动等待游戏连上来）。

## 数据所有权

服务端（游戏进程）是状态来源和权威。客户端完全不可信。

| 服务端权威（游戏进程） | 客户端本地（一个人一份） |
|----------------------|------------------------|
| 节点状态（端口/防火墙/文件系统等） | 正在跑的 Exe 实例 |
| Flag 系统 | 终端历史 / UI |
| Sequencer 进度 | 主题色 / 特效 |
| Faction rank 和状态 | 通知/动画 |
| 连接关系 | 滚动位置 |

## 存储模型（AC 2026-06-21 确认）

所有网络节点共享同一条存储逻辑。玩家 ID 映射表 + 初始状态同步给每个人。
唯一不同的三样东西：支线任务、Flag、节点破解状态。其他全部共享。

## 与旧设计（md 文件）的差异

| 维度 | 旧设计（TAXCore 正式方案） | 当前实际 |
|------|--------------------------|---------|
| 服务端角色 | GameState 权威状态字典 | 完整游戏实例 |
| 验证层 | VERT 抽出的纯函数 | ❌ 未实现，游戏本身做验证 |
| 协议 | XML | 冒号文本 EVENT:TYPE:data |
| 冲突处理 | version++ + first-write-wins | ❌ 未实现 |
| 入网同步 | NodeManifest → 增量差异 | ❌ 未实现 |
| 服务端部署 | 无头服务器，可跑 Linux | ❌ 必须 Windows + 屏幕 + 音频 |
| 开发分工 | VERT=服务端, AC=客户端, LDT=KE | AC 全包 |

## 未来迁移路径

主机模式 → 纯 C/S 的过渡：
1. 先在主机模式下跑通端到端流程（事件 → Pipe → LiteNetLib → 远程客户端）
2. 抽 HostGameState 层：把游戏当前状态快照序列化，不走游戏渲染
3. 抽验证逻辑：事件处理中校验节点是否存在、端口是否有效
4. 替换游戏进程为纯 .NET 控制台：复用抽出来的 GameState + 验证逻辑
