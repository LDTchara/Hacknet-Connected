# 准备大厅（开局前）

终端执行 `start` 后不再立刻开局，而是先开放准备大厅：等客户端加入、所有人准备好之后，服务端先进入游戏，准备完毕后再放客户端进来。

> 状态：大厅、聊天、全员暂停 / 掉线原地重连、阶段预设（见 README.Phases.md）已写完，**未实测**。

## 流程

1. 终端 `login` → `start`：照旧查玩家数、设置种子，然后**开放大厅**。服务端游戏弹出大厅界面。
2. 客户端在账户列表点 **Login**：进入客户端大厅界面，用这个账户名加入大厅。
3. 每个人（服务端主机 + 所有客户端）都可以随时点 **Ready / Cancel Ready**。
4. 所有在场的人都准备好时：
   - 客户端人数 = PlayersCount（满员）→ 直接开局。
   - 人数不足 → 服务端界面弹出确认框 **NOT ENOUGH PLAYERS**：
     - **Force Start**：强制开始（不建议，扩展的剧情预设通常会出问题）。
     - **Wait for players**：主机取消准备，继续等人。
   - 弹框期间有人取消准备、加入或离开，弹框会自动收回。
5. 开局：服务端关闭大厅界面、进入游戏。游戏加载完、世界种子发出后再等 1.5 秒，通知终端"准备完毕"。终端随即通知大厅里的客户端，客户端自动进入游戏。
6. 游戏开始后，新加入或重新登录的客户端在大厅界面直接看到 **Start Game**，点了就进游戏。

## 聊天

- 两个大厅界面右侧都有聊天框：直接打字（支持输入法中文、Ctrl+V 粘贴），**Enter** 发送，**Backspace** 删除。每条最多 200 字。
- 发送者由终端按连接身份盖上，客户端冒充不了别人。服务端主机的消息前面带 `[SERVER]`，显示为橙色。
- 终端保留最近 50 条，新加入的人能看到；终端控制台也会打印 `[大厅聊天]`。每次 `start` 清空。
- 只有已加入大厅的人能发言。游戏里看不到大厅聊天（游戏里用原有的 IRC 聊天）。

## 全员暂停与掉线

暂停闸门取自 Freezer：暂停时跳过 `Game1.Update`、`Game1.Draw` 和文字输入，屏幕显示 **GAME PAUSED** 和原因。只在游戏中生效，大厅和菜单不会被冻住。网络、心跳、管道都挂在 `Game1.Update` 的后置补丁上，暂停期间照常工作。

- **心跳**：客户端每 2 秒发 `PING`，终端回 `PONG`。时间按真实时钟算，暂停期间也照常走。
- **客户端掉线**（6 秒没收到 `PONG`，或连接断开）：
  1. 立刻冻结本机并本地存档，后台每 5 秒重连。
  2. 连上后以 resume 方式重新加入（不传存档）。服务器还在这一局时**原地继续，不用读档**。
  3. 服务器已经不在这一局（终端重开、重新 `start` 了）时，才退回准备大厅。
- **终端发现游戏中的客户端超时或断开**：通知服务端和所有客户端**全员暂停**，提示 "Waiting for P2 xxx to reconnect"。他回到游戏后自动解除。
- **服务端手动控制**：
  - 游戏里按 **F8** 全员暂停，按 **F9** 强制继续。强制继续会解除所有暂停，不再等掉线的人；被放弃等待的人回来之前不会再触发暂停。
  - 终端也可以用 `pause` / `resume`。
- **大厅里掉线**：每 5 秒自动重连，连上后自动重新加入。

## 规则

- **名额只算客户端**，上限是 profile 的 `PlayersCount`（终端 `options` 可看，首次 `start` 时从 `Players-Ser.xml` 读取）。`PlayersCount` 为 0 时不限人数，也不会弹"人数不足"。
- 满员后，再来的客户端会看到 **The server is full**，可以点 **Try Again** 重试。
- 服务端可以在大厅界面点某个客户端后面的 **Kick** 把他移出（只在开局前可用）。被移出的玩家可以点 **Rejoin** 或重新登录再次加入。
- 游戏中途有空位时，新玩家也可以加入。
- 大厅状态只存在终端内存里：每次重新开终端、重新 `start` 都会重新进入大厅。
- 同一个账户名从新连接加入时，旧连接会被断开（多半是掉线后旧连接还没超时）。

## 顺带修正：玩家身份改在加入大厅时确定

以前客户端一打开账户列表，就用**列表里第一个账户名**连接服务器（为了提前拿种子），终端在这时就登记了玩家身份、查了存档。如果最后登录的不是第一个账户，玩家名和服务端存档（`HAS_SAVE` / `NO_SAVE`）都会是错的。

现在：
- **连接（HELLO）**：只做临时登记，并请求世界种子。
- **加入大厅（LOBBY_JOIN）**：用真实账户名确定 PlayerId、检查并发送服务端存档、发 `WELCOME` / `PLAYER_DATA`、通知服务端（`SYNC_JOIN`）、广播玩家列表。
- 没有加入大厅的连接不会出现在玩家列表里，它们发来的事件、邮件、同步消息也会被忽略。

## 终端命令

| 命令 | 作用 |
|---|---|
| `start` | 开放准备大厅（已开放或已开局时会拒绝） |
| `pause` | 全员暂停（游戏开始后） |
| `resume` | 强制继续：解除所有暂停，不再等掉线的人 |
| `lobby` | 查看大厅阶段、人数和每个人的准备状态 |
| `lobby kick <id>` | 把客户端移出大厅（`lobby` 列表里 `[P2]` 的 2，只在开局前可用） |

## 测试步骤（建议）

1. 用 `build.bat` 编译，把 `Output\Server`、`Output\Client` 的 dll 和 `Output\Server\Terminal` 部署好。**三边必须一起更新**：旧客户端连新终端拿不到身份，新客户端连旧终端会一直停在 "Connecting to the lobby"。
2. 开终端 → 服务端游戏点 `[Start Server]` → 终端按 Y → `login` → `start`。确认服务端弹出大厅界面，显示 `Clients: 0 / N`。
3. 客户端：`[Connect to Server]` → 选服务器 → 选**不是第一个**的账户点 Login。确认大厅里显示的是这个账户名。
4. 满员测试：把 PlayersCount 设小再连第二个客户端，应看到 "The server is full"。设置方法：新建服务器时在 `create` 里 `set playerscount 1`；已有服务器则关掉终端，把 `Storage/Storages.ini` 里该服务器的 `PlayersCount=` 改成 1 再重开。
5. 准备测试：
   - 只有一个客户端时，两边都点 Ready，服务端应弹出 NOT ENOUGH PLAYERS。点 Force Start，服务端先进游戏，大约 1.5 秒后客户端自动进入。
   - 满员时两边都点 Ready，应直接开局，不弹框。
6. 移出测试：服务端点 Kick，客户端显示 "You were removed..."，点 Rejoin 应能回来。
7. 中途加入：开局后，另一个客户端登录，大厅应显示 "The game is already running" 和 Start Game。
8. 聊天：两边各发几条，确认双方都能看到、名字正确；之后新加入的客户端能看到之前的记录。
9. 全员暂停：游戏中拔掉某个客户端的网线（或让它的进程卡住超过 6 秒）。所有人都应显示 GAME PAUSED 和 "Waiting for ..."；恢复网络后应自动继续，掉线的那个客户端不用读档。
10. 强制继续：重复上一步，服务端按 F9，其他人应继续；掉线的人回来后原地继续。
11. 手动暂停：服务端按 F8 全员暂停，再按 F9 继续。
12. 终端重开：游戏中关掉终端，客户端冻结并重连；重开终端、`login`、`start` 后，客户端应退回大厅重新加入。

## 已知限制

- **开局失败会卡住**：如果服务端开局失败（例如游戏报错），终端会一直停在"服务端正在进入游戏"，只能重开终端。
- 终端关闭后，掉线的客户端会一直每 5 秒重试，直到点 Back。

## 已知限制：暂停与进度

- **延时动作**：`ActionDelayer` 用真实时间计时（同 Freezer），暂停期间到期的延时动作会在恢复后一起执行。
- **被放弃等待的人**：服务端强制继续后，掉线的人回来时原地解冻，但掉线期间世界的变化要靠 HNC.Sync 全量同步和 `refresh fs` 追上，之前的事件不会补发。
- **进程重启后重新登录**：仍是旧逻辑，终端有存档就覆盖本地；如果终端那份更旧，进度会落后。之前讨论的存档版本戳方案还没做。
